# 説明可能性

## 何が問題か

判断の理由を示せないシステムを、人に影響する決定に使ってよいか。
使ってよいとすれば、どの程度の説明が必要か。

技術的には、性能と解釈可能性の間に取引があるとしばしば言われます。
ただしこの前提自体が争われており、高い性能を保ったまま解釈可能なモデルを
作れる領域は少なくない、という主張もあります。

## 具体的な現れ方

- 融資を断られた人が、理由を尋ねても「総合的な判断」としか返らない
- 事後的な説明手法が示す「重要な特徴」が、実際にモデルが用いた根拠と
  一致する保証がない
- 説明が形式的に提供されても、それを使って異議を申し立てる手段がない

三つ目は見落とされがちです。説明は、それによって**何かができる**ときに
はじめて意味を持ちます。

## 各立場からの見え方

**功利主義** — 説明の要求が精度を下げるなら、全体の厚生は減りうる。
説明は目的ではなく手段であり、費用対効果で判断される。

**義務論** — 説明を受けることは権利である。理由を示されない判断に服することは、
自分に関わる決定の主体から降ろされることを意味する。精度が高くても代替できない。

**リバタリアニズム** — 契約に明示されていれば足りる。不透明さを承知で
契約した者に、事後の説明を求める根拠は弱い。ただし独占的地位では話が変わる。

**ロールズ** — 基本構造に関わる決定は、理にかなった市民が受け入れうる理由に
よって正当化されねばならない。「モデルの出力」はこの意味での公共的理由に
ならない。説明可能性は正統性の条件である。

**共同体論** — 説明の相手は個人だけでなく共同体でもある。その仕組みが
共同体の価値と整合するかを問える形での開示が求められる。

**潜在能力アプローチ** — 説明は異議申立ての前提であり、実質的な自由の一部。
理解可能で、行動に移せる形でなければ意味がない。

## 未解決の点

- 「説明」が何を指すか。因果的な理由か、反実仮想か、簡略化した近似か
- 説明を義務づけると、説明しやすい変数だけが使われ、かえって質が下がる恐れ
- 企業秘密や、システムの悪用（gaming）との衝突
