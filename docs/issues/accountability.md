# 答責性

## 何が問題か

アルゴリズムによる判断が害をもたらしたとき、誰が責任を負うのか。

データを集めた者、モデルを作った者、それを製品に組み込んだ者、運用の
方針を決めた者、現場で出力に従った者。関与者が多く、それぞれの寄与が
小さいとき、責任は誰にも帰属しないように見えます。この構造は
「多くの手の問題」と呼ばれます。

## 具体的な現れ方

- 現場の担当者が「システムがそう判断した」と述べ、開発側は「最終判断は
  人間が行う設計だ」と述べる。双方が相手を指す
- 人間による確認が形式化し、承認ボタンを押すだけの手続きになる
- 学習データの偏りに起因する害について、データの提供元まで責任が遡らない

## 各立場からの見え方

**功利主義** — 責任は、将来の害を最も効果的に減らせる者に配分するのが良い。
抑止効果の観点から、監督責任を組織に負わせる設計が支持されやすい。

**義務論** — 責任は行為者に帰属する。因果的な寄与が小さくとも、その判断に
関与した者は道徳的な責任を免れない。組織への転嫁は、個人の責任を消さない。

**リバタリアニズム** — 契約と過失の枠組みで処理する。事前に責任の所在を
定めた合意があれば、それに従う。

**ロールズ** — 個人の帰責より、**制度の設計**を問う。害が生じたときに救済に
たどり着けない構造そのものが、基本構造の欠陥として批判される。

**共同体論** — 役割に伴う責任を重視する。医師が診断支援を用いる場合、
医師であることに伴う責任は、道具の使用によって減じない。

**潜在能力アプローチ** — 被害者が救済にたどり着けるかを基準にする。
誰が悪いかの特定より、是正の経路が実際に機能しているかを問う。

## 未解決の点

- 人間による確認を要件にすると、形式的な承認を生む（自動化バイアス）
- 責任を組織に集約すると、個人の判断が空洞化する恐れがある
- 国境をまたぐ供給網で、どの法域の基準を適用するか
